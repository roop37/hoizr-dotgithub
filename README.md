# hoizr-dotgithub

Shared community files for every Hoizr repository. Each project README links here for contributing guidelines, the code of conduct, the security policy and support. For the project itself, start with the [Hoizr walkthrough](https://github.com/roop37/hoizr-walkthrough).

## What is here

| File | Purpose |
|---|---|
| [`profile/README.md`](profile/README.md) | A one-page overview of the Hoizr project and its repositories |
| [`CONTRIBUTING.md`](CONTRIBUTING.md) | How the repositories are organised and how to contribute |
| [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) | Contributor Covenant 3.0 |
| [`SECURITY.md`](SECURITY.md) | How to report a vulnerability privately |
| [`SUPPORT.md`](SUPPORT.md) | Where to ask questions and what to include |
| [`.github/ISSUE_TEMPLATE/`](.github/ISSUE_TEMPLATE) | Issue forms for bugs, feature requests and docs, plus the template chooser config |
| [`.github/pull_request_template.md`](.github/pull_request_template.md) | A pull request description template |
| [`LICENSE`](LICENSE) | MIT License for the contents of this repository |

## Using these files in a Hoizr repository

GitHub only applies community files automatically when they live in a repository named exactly `.github`, and for a personal account that would affect every repository the account owns. These files therefore live here and are linked from each project README instead.

To give a single repository the issue forms and pull request template, copy `.github/ISSUE_TEMPLATE/` and `.github/pull_request_template.md` into that repository. The issue forms add the `bug`, `enhancement` and `documentation` labels, which are GitHub's default labels.

## Contributing to these files

Open a pull request with the change and a short note on why it is needed.
